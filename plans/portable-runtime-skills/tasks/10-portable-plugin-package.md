# Build a filtered portable plugin package

Type: task
Status: open
Blocked by: 05
Test first: yes

First record the official portable plugin layout in `references.md` (its "Portable plugin layout" entry): the manifest's name and location, its required fields, the skills layout and the local marketplace format, with links and the date read. Build to that record, not to memory. The root `plugin.json` below is the planning guess; follow the record where they differ and say so in the Answer.

Add `scripts/package-plugin.sh` and package metadata templates that build a portable Agent Plugins artifact from the canonical sources and Codex renderer. The artifact has a root `plugin.json`, generated `skills/`, required scripts and shared resources, but no Claude-only skill, development plan, test fixture, local credential or unrelated repository file.

The command takes an explicit output directory and a `--check` mode. It refuses an existing nonempty destination unless it contains a marker proving it was generated by this script and the caller passes `--force`. `--check` builds under a validated temporary directory, validates JSON, skill frontmatter, `agents/openai.yaml`, relative references, executable paths and runtime eligibility, then cleans up without dirtying the repository. Produce a manifest of packaged paths and omitted runtime-specific skills for auditability.

Add a local marketplace example that points to a generated package without embedding an absolute machine path. Do not publish, add credentials or claim that the package passed public directory review.

## Not in this ticket

- Public submission, signing, release upload, MCP configuration or an app connector.
- Packaging the Claude-only `drive-flow` skill for Codex or ChatGPT.

## Done when

- The "Portable plugin layout" entry of `references.md` has no `<` placeholder line left and names at least one link.
- `bash scripts/package-plugin.sh --check` exits 0, reports a valid portable manifest, all included skills and the explicitly omitted unsupported skills, and leaves `git status --porcelain` unchanged.
- Building into an empty temporary directory creates `plugin.json`, a skills directory for every Codex-supported skill, required scripts and a deterministic path manifest; it contains no `drive-flow` or `.claude` path.
- A second build into that nonempty directory is refused; `--force` replaces only a directory carrying the package marker, while an unmarked directory remains untouched.
- Tests corrupt a manifest, a skill reference and a runtime declaration; validation fails each fixture with the affected path.
- `bash tests/run.sh` exits 0, and two package builds from the same commit have identical manifests.
